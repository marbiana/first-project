## Порядок завершения

1. Получить актуальный код и примеры WB-проектов.
2. Собрать калькулятор с воспроизводимым demo и контрольными примерами.
3. Собрать финансовый pipeline и проверить суммы/знаки операций.
4. Добавить скриншоты, итоговые примеры и подтверждённые результаты.
5. Выбрать акцент под вакансии и публичный контакт.
6. Перенести profile/README.md в публичный marbiana/marbiana.
7. Закрепить два WB-проекта и один-два завершённых учебных проекта.

## Что требует проверки перед публикацией учебного кода

- Справа от README не считать наличие Dockerfile доказательством готовности.
- Спринт 3: связать SQL-задачи с DAG, согласовать пути SQL и стратегию staging.
- Спринт 7: выбрать актуальные версии, проверить даты, ключи событий, часовые пояса и дубли пар.
- Спринт 8: проверить checkpoint, повторные записи и обработку ошибок.
- Спринт 9: найти или написать полноценные обработчики.
- SQL-витрина покупателей: проверить месячный ключ и обновление инкремента.
- Проверить историю на секреты. Удаление из текущего файла не удаляет их из предыдущих коммитов.
- Для рабочей программы подтвердить право публикации; данные компании заменить синтетическими.

## Критерий готовности

Рекрутер видит задачу и результат с первого экрана.
Технический руководитель может запустить demo по README и сверить результат на контрольных данных.
В описании нет возможностей, которые ещё не реализованы, и эффектов без измерений.
